# python-eks1 — Working Notes

## Project
- **Blueprint**: python-eks@1.1.0 (Python API on Amazon EKS)
- **Cloud**: AWS us-east-1
- **Target**: EKS (managed node group, t3.medium x2)
- **Database**: RDS Postgres db.t4g.micro (module=postgres)
- **VCS**: GitHub

## Decisions
- Blueprint materialised at scope=design then scope=files — all 34 files from the template are the canonical source. Only the `Blueprint` tag in infra/versions.tf was corrected (was `nodejs-eks`, now `python-eks`).
- No NAT gateway (blueprint default) — nodes reach ECR/control plane over their public interface. Private subnets carry RDS only. Add NAT + move node group to private if egress control is needed.
- RDS Postgres 16, single-AZ db.t4g.micro, encrypted, 7-day backups, skip_final_snapshot=true (reversible deploy posture).
- KMS key for EKS secret envelope encryption with key rotation enabled.
- Pipeline: 13 stages — 7 parallel gates (lint, test, sast/semgrep, secrets_scan/gitleaks, license_scan, sbom/cyclonedx, iac_scan/trivy+checkov) → provision → build_push → image_scan/trivy → configure (migrations Job + rollout) → verify (NLB health check) → notify.
- Destroy workflow handles Kubernetes-created LB cleanup before terraform destroy (LB blocks VPC teardown otherwise).
- DB password: generated by `random_password.db` in Terraform (alphanumeric, 32 chars). No DB_PASSWORD pipeline secret needed — password flows through RDS state → terraform output → Kubernetes Secret in configure stage.

## Known Pitfalls / Gotchas
- EKS cluster creation takes 12-15 min; provision stage has timeout_minutes=45 — normal.
- RDS in a private subnet with no NAT: the configure stage reads the DB URL from terraform output and creates the K8s Secret. The app connects from within the cluster (VPC internal).
- The NLB is created by Kubernetes (Service type=LoadBalancer), NOT by Terraform. Destroy workflow must delete the K8s service first so AWS deletes the LB before terraform destroy runs — the destroy stage handles this.
- EKS public endpoint is open to 0.0.0.0/0; required for GitHub-hosted runners. Recorded exception in .trivyignore.
- db.t4g.micro is ARM-based (Graviton2) — supported in us-east-1.
- PGSSLMODE=verify-full + RDS CA bundle baked into the image at build time from AWS truststore URL.
- Test suite runs without DATABASE_URL intentionally (database=none path). DB connectivity covered by live readiness probe.
- test_project secrets_scan step: curl not on UDAP sandbox — this is a known sandbox gap, not a CI issue. GH ubuntu-latest always has curl. Do not modify the stage to work around the sandbox.
